# Git 충돌(Conflict) 해결법

> 팀원 여러 명이 **같은 파일의 같은 줄**을 각자 고쳤을 때 생기는 문제와 해결 방법.

---

## 충돌이 왜 생기나

| | |
|---|---|
| **A가 한 일** | `schema.sql` 10번째 줄을 `input_type` 으로 고치고 푸시 |
| **B가 한 일** | 같은 파일 10번째 줄을 `source_type` 으로 고침 |
| **B가 pull 하면** | 깃: "10번째 줄을 둘 다 고쳤는데 뭘 남길까? **나는 못 정해**" → **충돌** |

**중요:** 충돌은 에러가 아니라 **"둘 중에 뭘 남길지 사람이 골라달라"** 는 요청입니다. 깃이 마음대로 하나를 버리면 누군가의 작업이 날아가니까 일부러 멈추는 겁니다.

다른 줄을 고쳤으면 깃이 알아서 합쳐줍니다. **같은 줄**을 고쳤을 때만 충돌이 납니다.

---

## 충돌이 나면 보이는 것

파일 안에 이런 게 생깁니다.

```
<<<<<<< HEAD
    input_type      VARCHAR(20)  -- 내가 쓴 내용
=======
    source_type     VARCHAR(20)  -- 상대방이 쓴 내용
>>>>>>> 6a054897af343cf38a62df7f6a7de821f5a43545
```

| 기호 | 뜻 |
|---|---|
| `<<<<<<< HEAD` | 여기부터 **내 것** 시작 |
| `=======` | 경계선 (위 = 내 것 / 아래 = 상대 것) |
| `>>>>>>> 6a054...` | 여기까지 **상대 것**. 뒤의 글자는 상대방 커밋 번호 |

**이 세 줄은 깃이 표시용으로 끼워넣은 것이라, 반드시 지워야 합니다.**

---

## ⚠️ 가장 많이 하는 실수

**"해결됨" 체크만 하고 실제로는 안 고치는 것.**

IntelliJ나 소스트리에서 충돌 파일을 `Add`(= `git add`) 하면 깃은 **"아, 사람이 다 골랐구나"** 하고 믿어버립니다. 파일 안을 들여다보지 않습니다.

그래서 `<<<<<<<` 기호가 그대로 남아 있어도 **커밋이 되고 푸시까지 됩니다.** 그러면:

- `.sql` 파일 → **실행 자체가 안 됨**
- `.html` 파일 → 화면에 `<<<<<<< HEAD` 가 글자로 그대로 보임
- `.java` 파일 → **컴파일 에러**

**반드시 파일을 열어서 기호를 직접 지워야 합니다.**

---

## 해결 방법 ① IntelliJ (추천)

1. `pull` 하면 **`Conflicts` 창**이 자동으로 뜹니다. (안 뜨면 상단 `Git` → `Resolve Conflicts`)
2. 충돌 파일을 고르고 **`Merge`** 버튼 클릭
3. 창이 **세 칸**으로 갈라집니다

   | 왼쪽 | 가운데 | 오른쪽 |
   |---|---|---|
   | 내 버전 | **최종 결과** (여기가 실제 파일) | 상대 버전 |

4. 충돌 구간마다 화살표 **`>>`** / **`<<`** 를 눌러 **가져올 쪽을 선택**
   - 왼쪽 것만 쓰기 → 왼쪽 화살표
   - 오른쪽 것만 쓰기 → 오른쪽 화살표
   - **둘 다 필요하면** → 양쪽 다 누르거나 가운데 칸에서 직접 타이핑
   - 필요 없는 쪽은 **`X`** 로 버리기
5. 모든 구간 처리 후 **`Apply`**
6. 커밋 → 푸시

> **가운데 칸은 직접 수정할 수 있습니다.** 두 버전을 섞어야 할 때는 그냥 타이핑하세요.

---

## 해결 방법 ② 직접 손으로 (제일 확실함)

1. 충돌난 파일을 에디터로 엽니다
2. `Ctrl + F` 로 **`<<<<<<<`** 검색
3. 남길 내용만 남기고 **기호 3줄을 전부 지웁니다**

**고치기 전**
```
<<<<<<< HEAD
    input_type      VARCHAR(20)
=======
    source_type     VARCHAR(20)
>>>>>>> 6a054897af343cf38a62df7f6a7de821f5a43545
```

**고친 후** (내 것을 남기기로 했다면)
```
    input_type      VARCHAR(20)
```

4. 파일에 충돌 기호가 **하나도 없는지** 다시 검색해서 확인
5. 저장 → 커밋 → 푸시

---

## ✅ 커밋 전 최종 확인 (꼭 하세요)

터미널에서 이 명령어 한 줄이면 충돌 기호가 남았는지 다 찾아줍니다.

```bash
git grep -n "^<<<<<<<\|^=======$\|^>>>>>>>"
```

- **아무것도 안 나오면** → 깨끗함, 커밋해도 됨
- **뭔가 나오면** → 그 파일/줄에 기호가 남아 있음, 지우고 다시 확인

추가로:
- `.sql` 고쳤으면 → Workbench에서 실행해보기
- `.java` 고쳤으면 → 빌드 돌려보기
- `.html` 고쳤으면 → 브라우저로 열어보기

## 어느 쪽을 남겨야 하나

정답이 정해진 게 아니라 **상황마다 다릅니다.**

| 상황 | 어떻게 |
|---|---|
| 내가 더 최신 작업을 했다 | 내 것(HEAD) 남기기 |
| 상대가 더 최신이다 | 상대 것 남기기 |
| **둘 다 필요한 다른 작업이다** | **둘 다 남기기** (제일 흔함!) |
| 모르겠다 | **지우기 전에 상대에게 물어보기** |

> ⚠️ 헷갈리면 **절대 혼자 판단해서 지우지 마세요.** 상대방의 하루치 작업이 사라질 수 있습니다. 카톡으로 물어보는 게 30초면 됩니다.

## 충돌을 애초에 줄이는 법

1. **작업 시작 전에 항상 `git pull`** — 최신 상태에서 시작
2. **자주 커밋하고 자주 푸시** — 오래 묵힐수록 충돌이 커짐
3. **담당 파일을 나누기** — 같은 파일을 둘이 동시에 건드리지 않기
4. **큰 변경은 미리 공지** — "나 지금 schema.sql 크게 고칠게" 한마디

## 망했을 때 되돌리기

### 병합을 아예 취소하고 처음으로
```bash
git merge --abort
```
`pull` 하기 전 상태로 완전히 되돌아갑니다. **아직 커밋 안 했을 때만** 됩니다.

### 특정 파일만 상대 것으로 통째로 받기
```bash
git checkout --theirs 파일경로
git add 파일경로
```

### 특정 파일만 내 것으로 통째로 받기
```bash
git checkout --ours 파일경로
git add 파일경로
```

---

## 참고: 다른 에러와 헷갈리지 않기

### `non-fast-forward` (푸시 거절)

```
! [rejected] feature/entities -> feature/entities (non-fast-forward)
hint: Updates were rejected because the tip of your current branch is behind
```

**이건 충돌이 아닙니다.** "깃허브에 너보다 최신 게 있으니 먼저 받아라"는 뜻입니다.

```bash
git pull
```

→ 이때 충돌이 나면 위의 방법으로 해결, 안 나면 그냥 푸시하면 됩니다.

> ⛔ **`git push --force` 는 쓰지 마세요.** 남의 작업을 통째로 지웁니다.

## 한 줄 요약

> 충돌 = 깃이 **"둘 중 뭘 남길지 골라줘"** 라고 묻는 것.
> **`<<<<<<<` `=======` `>>>>>>>` 세 기호를 파일에서 완전히 지워야** 해결된 것.
> 커밋 전에 `git grep -n "^<<<<<<<"` 로 한 번 확인하기.
