# 로그인 · 토큰 사용법 (백엔드 팀 전용)

> "지금 로그인한 사람이 누구인지" 다른 기능(업로드, 기록, 여행 등)에서 어떻게 가져다 쓰는지 정리.

---

## 흐름

1. 클라이언트가 `POST /auth/login` 으로 이메일·비밀번호를 보냄
2. 서버가 맞으면 `accessToken`(JWT)을 응답으로 줌
3. 클라이언트는 이후 모든 요청에 헤더를 붙여서 보냄:
   ```
   Authorization: Bearer <accessToken>
   ```
4. `JwtAuthenticationFilter` 가 이 헤더를 읽어서 토큰이 유효하면 "이 요청은 userId=3 인 사람이 보낸 것"이라고 표시해둠
5. 컨트롤러는 그 userId 를 그냥 파라미터로 받아 쓰면 됨 (직접 헤더 파싱 X)

토큰이 없거나, 만료됐거나, 변조됐으면 컨트롤러까지 오지도 않고 **401**이 자동으로 나갑니다. 컨트롤러 코드에서 "로그인 안 했으면 에러 내기" 같은 걸 직접 짤 필요 없음.

---

## 내 컨트롤러에서 "지금 로그인한 사람" 쓰기

파라미터에 `@CurrentUserId Long userId` 만 붙이면 끝.

```java
@RestController
@RequestMapping("/diaries")
public class DiaryController {

    @GetMapping
    public List<DiaryResponse> myDiaries(@CurrentUserId Long userId) {
        return diaryService.findAllByUser(userId);
    }

    @PostMapping
    public DiaryResponse create(@CurrentUserId Long userId, @RequestBody DiaryRequest req) {
        return diaryService.create(userId, req);
    }
}
```

`import com.example.pinkok_backend.security.CurrentUserId;` 만 추가하면 됩니다. 별도 설정 필요 없음 (`@AuthenticationPrincipal` 을 짧게 감싼 것뿐).

## 서비스 레이어(컨트롤러가 아닌 곳)에서 필요할 때

컨트롤러에서 파라미터로 받아 서비스에 넘기는 게 기본이지만, 정 필요하면:

```java
Long userId = SecurityUtils.currentUserId();
```

## 인증이 필요 없는 API를 새로 만들 때

기본적으로 **모든 API는 로그인이 필요**합니다 (`SecurityConfig`). 로그인 없이 열어야 하는 API(예: 공개 조회)를 새로 만들면 `SecurityConfig` 의 `permitAll()` 목록에 경로를 추가해야 합니다. 그 전엔 자동으로 401 이 납니다 — 실수로 막힌 게 아니라 기본값이 "잠김"입니다.

```java
.authorizeHttpRequests(auth -> auth
        .requestMatchers("/auth/signup", "/auth/login").permitAll()
        // 새로 열 경로가 있으면 여기 추가
        .anyRequest().authenticated())
```

## Postman/curl 로 테스트할 때

```bash
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"email\":\"me@test.com\",\"password\":\"pass1234\"}"
```

응답의 `accessToken` 값을 복사해서, 인증이 필요한 API에는 항상 이 헤더를 붙이기:

```bash
curl http://localhost:8080/users/me \
  -H "Authorization: Bearer eyJhbGciOi..."
```

Postman이면 `Authorization` 탭 → Type `Bearer Token` → 값 붙여넣기.

## 자주 나는 에러

| 증상 | 원인 |
|---|---|
| 만든 API가 이유 없이 401 | 헤더 안 붙임 / 토큰 만료(1시간) / `SecurityConfig` 에 permitAll 안 함 |
| 로그인은 되는데 그 다음 요청이 401 | `Authorization: Bearer <토큰>` 형식 확인 (Bearer 뒤 띄어쓰기 필수) |
| `@CurrentUserId Long userId` 가 null | 그 경로가 `permitAll()` 이면 인증 안 거치므로 principal 이 없음. 로그인 필요한 API인지 확인 |

궁금한 거 있으면 정훈한테 물어보기.
