# 비밀번호 변경 · 재설정 API

두 가지가 있습니다.

| | 언제 | 로그인 | 엔드포인트 |
|---|---|---|---|
| **변경** | 설정 화면에서 바꿀 때 | 필요 | `PATCH /users/me/password` |
| **재설정** | 비밀번호를 잊었을 때 | 불필요 | `POST /auth/password-reset/request` → `verify` → `confirm` |

새 비밀번호 규칙은 회원가입과 같습니다: **8~64자**.

> 틀린 입력(현재 비밀번호 불일치, 잘못된 인증번호 등)은 **401이 아니라 400**으로 옵니다.
> 프론트의 axios 인터셉터가 401을 "액세스 토큰 만료"로 보고 토큰 갱신을 시도하기 때문입니다.

---

## 1. 비밀번호 변경 (로그인한 상태)

`PATCH /users/me/password` — `Authorization: Bearer <accessToken>`

```json
{ "currentPassword": "oldpass12", "newPassword": "newpass34" }
```

**200 응답은 로그인 응답(`TokenResponse`)과 같은 모양입니다.**

```json
{ "tokenType": "Bearer", "accessToken": "...", "expiresIn": 3600, "refreshToken": "...", "user": { ... }, "newUser": false }
```

- 비밀번호를 바꾸면 **다른 기기의 로그인은 모두 끊깁니다.**
- 지금 기기가 로그아웃되지 않으려면, **응답의 `accessToken`/`refreshToken`으로 저장값을 바꿔야 합니다** (로그인 직후와 똑같이 저장).

| 상태 | 의미 |
|---|---|
| 400 | 현재 비밀번호가 틀림 / 새 비밀번호가 현재와 같음 / 8자 미만 / 소셜 로그인 계정(비밀번호 없음) |
| 401 | 액세스 토큰 없음·만료 (평소처럼 갱신 후 재시도) |

---

## 2. 비밀번호 재설정 (잊은 상태) — 3단계

```
[이메일 입력] → request → (메일로 6자리 인증번호) → [번호 입력] → verify → resetToken → [새 비밀번호 입력] → confirm → 로그인 화면
```

### 1단계 `POST /auth/password-reset/request`
```json
{ "email": "me@example.com" }
```
- **항상 204**입니다. 가입된 이메일인지 알 수 없게 하려는 것이라, 없는 이메일·소셜 계정이어도 똑같이 204입니다.
- 인증번호는 **6자리, 10분** 유효합니다.
- 같은 이메일로 **60초 안에 다시 요청하면 메일이 안 갑니다**(204는 옵니다). 재발송 버튼에 60초 타이머를 두세요.
- 새 인증번호를 받으면 이전 번호는 못 씁니다.

### 2단계 `POST /auth/password-reset/verify`
```json
{ "email": "me@example.com", "code": "123456" }
```
→ 200
```json
{ "resetToken": "...", "expiresIn": 900 }
```
- `resetToken`은 **15분** 유효, **한 번만** 쓸 수 있습니다.
- 인증번호를 **5번 틀리면** 그 번호는 못 씁니다 → 1단계부터 다시.
- 400: 번호가 틀렸거나 만료됨 (`"인증번호가 올바르지 않거나 만료되었습니다."`).

### 3단계 `POST /auth/password-reset/confirm`
```json
{ "resetToken": "...", "newPassword": "newpass34" }
```
→ 204. 그 계정의 **모든 로그인이 끊기니** 로그인 화면으로 보내 새 비밀번호로 로그인하게 하세요.
- 400: 토큰이 만료됐거나 이미 썼음 (`"재설정 시간이 지났습니다. 인증번호부터 다시 받아 주세요."`).

### 현재 프론트 화면과의 차이
`비밀번호 재설정` 화면은 이메일 + 인증번호까지만 있고 새 비밀번호 입력칸이 없습니다.
(문구도 "재설정 링크 받기"입니다.) 위 흐름에 맞추려면 **인증번호 확인 후 새 비밀번호를 입력하는 단계**가 하나 더 필요합니다.

## 3. 메일 설정 (서버 담당)

- `spring.mail.*`이 **설정돼 있으면** 실제 이메일로 보냅니다.
- **설정이 없으면**(개발 중) 메일 대신 **서버 로그**에 `[메일 미설정] ... 인증번호: 123456`을 남깁니다. 팀 테스트 때는 서버 로그에서 번호를 확인하면 됩니다.
- 설정 방법은 `application.properties.example`의 "비밀번호 재설정 메일" 항목을 보세요. Gmail은 2단계 인증 후 **앱 비밀번호**가 필요합니다. 비밀번호는 절대 커밋하지 마세요.
- 메일 발송이 실패해도 응답은 204입니다(가입 여부가 새는 것을 막기 위해). 실패는 서버 로그에 남습니다.

---

## 4. Swagger로 시험하기

1. `POST /auth/password-reset/request`에 이메일을 넣고 실행 → 204
2. 서버 로그(또는 메일)에서 6자리 번호 확인
3. `POST /auth/password-reset/verify` → `resetToken` 복사
4. `POST /auth/password-reset/confirm`에 `resetToken`과 새 비밀번호 → 204
5. `POST /auth/login`에 새 비밀번호로 로그인
