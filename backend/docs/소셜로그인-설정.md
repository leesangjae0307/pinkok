# 소셜 로그인 (카카오 · 구글) 설정과 사용법

> 서버 코드는 완성돼 있지만, **카카오·구글 개발자 콘솔에서 앱을 등록하고 키를 서버에 넣어야** 실제로 동작합니다.
> 키를 넣기 전에는 `POST /auth/social/*` 가 `503 (로그인이 설정되지 않았습니다)` 을 돌려줍니다. 검증 없이 통과시키지 않기 위한 의도된 동작입니다.
> (콘솔 메뉴 이름은 제공자가 바꾸기도 해서, 아래 경로는 큰 흐름으로 보세요.)

---

## 1. 전체 흐름

```
[앱] 카카오/구글 SDK 로 로그인  →  토큰을 받음
[앱] POST /auth/social/kakao  {"token": "<카카오 액세스 토큰>"}
     POST /auth/social/google {"token": "<구글 ID 토큰>"}
[서버] 제공자에게 "이 토큰 진짜고, 우리 앱 것 맞아?" 확인 → 사용자 정보 받음
[서버] 처음이면 계정 자동 생성 → 우리 서비스의 accessToken / refreshToken 발급
[앱] 이후는 일반 로그인과 똑같음 (Authorization: Bearer ..., 401 이면 /auth/refresh)
```

- 앱이 서버에 보내는 건 **제공자 토큰 하나**뿐입니다. 비밀번호나 리디렉션 주소는 필요 없습니다.
- 서버는 토큰이 **우리 앱에 발급된 것인지**까지 확인합니다(카카오 `app_id`, 구글 `aud`). 다른 앱에서 받은 토큰은 401 입니다.

### 응답

일반 로그인(`POST /auth/login`)과 같은 모양에 `newUser` 가 있습니다.

```json
{ "tokenType": "Bearer", "accessToken": "...", "expiresIn": 3600, "refreshToken": "...",
  "user": { "id": 7, "email": "a@b.com", "username": "kakao_3fa9c01b", "nickname": "카카오닉", "avatar": { ... } },
  "newUser": true }
```

- `newUser: true` — 방금 계정이 만들어졌습니다. 앱은 이때 **닉네임·아바타·여행 취향 설정 화면**을 한 번 보여 주면 좋습니다.
  (`PATCH /users/me`, `PATCH /users/me/avatar`, `PUT /user-travel-styles` 로 바꿀 수 있습니다.)
- 일반 로그인 응답에도 `newUser: false` 가 들어갑니다 (기존 필드는 그대로).

### 계정이 만들어지는 규칙

| 항목 | 규칙 |
|---|---|
| `username` | 자동 (`kakao_3fa9c01b`, `google_...` 형태) |
| `nickname` | 제공자의 이름. 못 받으면 "여행자" |
| 아바타 | 기본 아바타 중 무작위 |
| 이메일 | 제공자가 **확인된 이메일**이라고 보증할 때만 저장. 동의 안 했거나 미인증이면 이메일 없는 계정 |
| 같은 이메일의 일반 계정이 이미 있으면 | **자동으로 합치지 않고 409** ("이메일과 비밀번호로 로그인해 주세요"). 이메일이 같다는 것만으로 같은 사람이라고 믿을 수 없기 때문 |
| 카카오 계정 ↔ 구글 계정 | 사용자 ID 가 같아도 서로 다른 계정 |
| 탈퇴한 계정 | 401 |
| 비밀번호 | 없음 — 소셜 계정은 이메일·비밀번호 로그인으로 들어올 수 없음 |

## 2. 카카오

### 콘솔에서 할 일 (developers.kakao.com)
1. **앱 ID 확인**: 내 애플리케이션 → 앱 정보의 **앱 ID(숫자)**. → 서버의 `KAKAO_APP_ID`
2. **카카오 로그인 사용 설정**: 제품 설정 → 카카오 로그인 → 활성화
3. **플랫폼 등록**: Android(패키지명 + 키 해시), iOS(번들 ID). 키 해시는 앱을 빌드하는 PC마다 다를 수 있습니다(팀원 PC도 각각 등록).
4. **동의 항목**: 닉네임(필수로 두는 걸 권장), 이메일(선택). 이메일 동의는 앱 상태에 따라 제한될 수 있는데, **이메일이 없어도 로그인은 됩니다.**
5. **네이티브 앱 키**: 프론트가 SDK 초기화에 씁니다(서버는 쓰지 않음). 프론트 담당에게 전달하세요.

### 서버 설정
```
KAKAO_APP_ID=<앱 ID 숫자>
```
(기존 `KAKAO_REST_API_KEY` — 장소 검색용 — 와는 별개입니다.)

### 앱(프론트)에서 보낼 것
카카오 SDK 로그인 결과의 **액세스 토큰**을 보냅니다.
```ts
// 예: @react-native-seoul/kakao-login  (※ 라이브러리 선택·사용법은 프론트 확인 필요)
const result = await login();                       // KakaoOAuthToken
const { data } = await api.post('/auth/social/kakao', { token: result.accessToken });
```

## 3. 구글

### 콘솔에서 할 일 (console.cloud.google.com)
1. 프로젝트 만들기 → **OAuth 동의 화면** 설정(앱 이름, 이메일, 테스트 사용자 등록)
2. **사용자 인증 정보 → OAuth 클라이언트 ID** 생성
   - **Android**: 패키지명 + SHA-1 인증서 지문(팀원 PC마다 다를 수 있음)
   - **iOS**: 번들 ID
   - **웹 애플리케이션**: 앱이 ID 토큰을 받으려면 보통 이 **웹 클라이언트 ID** 를 SDK 설정(`webClientId`)에 넣습니다. 이 경우 토큰의 `aud` 가 웹 클라이언트 ID 가 됩니다.
3. 만든 클라이언트 ID 들을 서버에 알려 줍니다.

### 서버 설정
```
GOOGLE_CLIENT_IDS=<웹 클라이언트 ID>,<안드로이드 클라이언트 ID>,<iOS 클라이언트 ID>
```
쉼표로 여러 개 넣을 수 있습니다. **토큰의 `aud` 가 이 목록에 있어야** 통과합니다. 모르겠으면 앱이 SDK 에 넣은 ID 를 모두 넣으세요.

### 앱(프론트)에서 보낼 것
구글 로그인 결과의 **ID 토큰**(액세스 토큰 아님)을 보냅니다.
```ts
// 예: @react-native-google-signin/google-signin  (※ 버전에 따라 반환 구조가 다름, 프론트 확인 필요)
GoogleSignin.configure({ webClientId: '<웹 클라이언트 ID>' });
const res = await GoogleSignin.signIn();
const { data } = await api.post('/auth/social/google', { token: res.data.idToken });
```

## 4. 서버에 설정 넣기

`application.properties`(로컬 전용, git 에 올라가지 않음)에 직접 적거나, 서버를 켜는 터미널에서 환경변수로 줍니다.

```
kakao.app-id=<앱 ID>
google.client-ids=<ID1>,<ID2>
```
```powershell
$env:KAKAO_APP_ID = "<앱 ID>"
$env:GOOGLE_CLIENT_IDS = "<ID1>,<ID2>"
.\gradlew.bat bootRun
```
키·ID 는 코드나 git 에 넣지 마세요 (`application.properties.example` 에는 자리만 있습니다).

## 5. 오류 코드

| 코드 | 의미 | 앱에서 |
|---|---|---|
| 200 | 성공 (`newUser` 로 신규 여부 확인) | 토큰 저장 |
| 400 | `token` 이 비었거나, 지원하지 않는 제공자(`kakao`, `google` 만) | 버튼 로직 점검 |
| 401 | 토큰 만료·위조·**다른 앱에서 발급된 토큰**, 탈퇴한 계정 | "다시 로그인해 주세요" |
| 409 | 같은 이메일의 일반 계정이 이미 있음 | 메시지 그대로 보여 주고 이메일 로그인으로 안내 |
| 502 | 카카오·구글 서버 호출 실패 | "잠시 후 다시 시도" |
| 503 | **서버에 카카오 앱 ID / 구글 클라이언트 ID 가 설정되지 않음** | 서버 담당에게 알림 |

## 6. 앱 없이 서버만 시험하기

1. 카카오·구글 쪽에서 **토큰을 하나 직접 받습니다.** 카카오 개발자 사이트의 로그인 테스트·토큰 발급 도구, 구글의 OAuth 2.0 Playground(ID 토큰은 `openid email profile` 범위로 받은 응답의 `id_token`)를 쓰면 됩니다.
2. 받은 토큰으로 호출합니다.
```bash
curl -X POST http://localhost:8080/auth/social/kakao -H "Content-Type: application/json" -d '{"token":"<토큰>"}'
```
3. 위의 설정(앱 ID / 클라이언트 ID)이 그 토큰이 발급된 앱과 **같은 앱의 값**이어야 401 이 나지 않습니다. (OAuth Playground 의 토큰은 Playground 자체 클라이언트 ID 로 발급돼서 `aud` 가 다릅니다. 그 ID 를 임시로 `GOOGLE_CLIENT_IDS` 에 넣고 시험할 수 있습니다.)
