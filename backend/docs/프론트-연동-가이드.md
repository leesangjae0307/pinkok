# 프론트 연동 가이드 (앱 ↔ 백엔드)

> 앱(React Native)에서 백엔드 API를 처음 붙일 때 필요한 것만 모았습니다.
> 요청/응답 필드의 전체 목록은 **Swagger** 가 항상 최신입니다: `http://<서버주소>:8080/swagger-ui/index.html`
> (로그인 없이 열림. 우측 상단 Authorize 에 accessToken 을 넣으면 바로 호출해볼 수도 있습니다.)

---

## 0. 먼저 고쳐야 할 것 — baseURL

현재 `frontend/src/api/axios.ts` 는 이렇게 돼 있습니다.

```ts
baseURL: 'http://YOUR_IP:8080/api',
```

**백엔드에는 `/api` 접두사가 없습니다.** 그대로 쓰면 모든 요청이 404 입니다. `/api` 를 빼주세요.

```ts
baseURL: 'http://<서버 IP>:8080',
```

| 실행 환경 | 서버 주소 |
|---|---|
| Android 에뮬레이터 | `http://10.0.2.2:8080` (에뮬레이터 안의 `localhost` 는 에뮬레이터 자신) |
| iOS 시뮬레이터 | `http://localhost:8080` |
| 실제 폰 | 서버 PC 의 사내/집 IP (`http://192.168.x.x:8080`), 같은 와이파이여야 하고 PC 방화벽에서 8080 허용 |

- `http://` (https 아님) 라서 Android 는 원래 막지만, 이 프로젝트의 **debug 빌드는 이미 허용**돼 있습니다
  (`android/app/src/debug/AndroidManifest.xml` 의 `usesCleartextTraffic="true"`). release 빌드로 시연할 땐 https 서버가 필요합니다.
- `timeout: 10000` 은 AI 요청(아래 3장)이 **즉시 응답**하는 구조라 괜찮습니다. 파일 업로드(영상)는 더 걸릴 수 있으니 업로드 요청만 `timeout: 60000` 으로 늘리세요.

## 1. 인증 (로그인 · 토큰 갱신)

자세한 배경은 `로그인-토큰-사용법.md`. 앱에서 해야 할 일만 요약합니다.

1. `POST /auth/signup` → 가입 / `POST /auth/login` → 로그인
2. 로그인 응답의 `accessToken`(1시간), `refreshToken`(14일)을 저장 (refreshToken 은 SecureStorage/Keychain 권장)
3. 이후 모든 요청에 `Authorization: Bearer <accessToken>`
4. 401 이 오면 `POST /auth/refresh {refreshToken}` → **새 accessToken 과 새 refreshToken 을 둘 다 저장 값에 덮어쓰기**
5. refresh 도 401 이면 로그인 화면으로

> ⚠️ refreshToken 은 **1회용**입니다. 한 번 쓰면 폐기되고, 폐기된 걸 다시 쓰면 그 사용자의 모든 토큰이 강제 로그아웃됩니다.
> 그래서 **동시에 여러 요청이 401 을 받았을 때 refresh 를 여러 번 보내면 안 됩니다.** 한 번만 보내고 나머지는 기다렸다가 새 토큰으로 재시도해야 합니다.

### axios 인터셉터 예시 (동시 401 처리 포함)

```ts
import axios, { AxiosError, InternalAxiosRequestConfig } from 'axios';
// tokenStore: accessToken / refreshToken 을 읽고 쓰는 모듈 (직접 구현)
import { tokenStore } from '../store/tokenStore';

const api = axios.create({ baseURL: 'http://<서버 IP>:8080', timeout: 10000 });

api.interceptors.request.use(config => {
  const token = tokenStore.accessToken;
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

let refreshing: Promise<string> | null = null; // 진행 중인 refresh 를 모든 요청이 공유

async function refreshAccessToken(): Promise<string> {
  // 인터셉터가 걸린 api 가 아니라 순수 axios 로 호출 (무한 루프 방지)
  const { data } = await axios.post(`${api.defaults.baseURL}/auth/refresh`, {
    refreshToken: tokenStore.refreshToken,
  });
  tokenStore.save(data.accessToken, data.refreshToken); // 둘 다 덮어쓰기
  return data.accessToken;
}

api.interceptors.response.use(
  res => res,
  async (error: AxiosError) => {
    const original = error.config as InternalAxiosRequestConfig & { _retried?: boolean };
    const isAuthCall = original?.url?.startsWith('/auth/');
    if (error.response?.status !== 401 || !original || original._retried || isAuthCall) {
      return Promise.reject(error);
    }
    original._retried = true;
    try {
      refreshing = refreshing ?? refreshAccessToken().finally(() => { refreshing = null; });
      const newToken = await refreshing;
      original.headers.Authorization = `Bearer ${newToken}`;
      return api(original);
    } catch (e) {
      tokenStore.clear();
      // 로그인 화면으로 이동 (navigation reset)
      return Promise.reject(e);
    }
  },
);

export default api;
```

## 2. 에러 응답 형식

모든 에러는 같은 모양입니다 (`에러-응답-형식.md`).

```json
{ "timestamp": "2026-10-03T21:10:00", "status": 400, "message": "사람이 읽을 메시지", "errors": { "필드": "이유" } }
```

- 사용자에게 보여줄 문구는 `error.response.data.message` 를 그대로 쓰면 됩니다 (한국어).
- `errors` 는 입력 검증 실패(400)일 때만 있고, 필드 이름별 이유입니다 → 입력창 밑에 표시.

| 코드 | 의미 | 앱 처리 |
|---|---|---|
| 400 | 값이 잘못됨 / 선행 조건 부족 | `message` 표시 |
| 401 | 토큰 없음·만료 | 1장의 refresh 흐름 |
| 403 | 이 여행의 팀원이 아님 | 접근 불가 안내 |
| 404 | 없는 리소스 | 목록 새로고침 |
| 409 | 충돌 (중복, 이미 처리됨, **오래된 제안**) | `message` 표시 후 새로 불러오기 |
| 422 | 요청은 맞는데 처리 불가 (예: 추천 장소를 지도에서 못 찾음) | `message` 표시 |

## 3. AI 기능 — "요청 → 폴링" 패턴

Gemini 호출은 10~30초 걸려서 **요청하면 바로 `202`/`PENDING` 을 돌려주고, 백그라운드에서 처리**합니다.
앱은 결과가 나올 때까지 상태를 조회(폴링)하면 됩니다.

```
POST /ai-requests            → 즉시 응답 {id, status:"PENDING", ...}
GET  /ai-requests/{id}       → 2~3초마다 조회
        status: PENDING → PROCESSING → SUCCESS | FAILED
```

- `SUCCESS` 이면 같은 응답의 `title`, `places[]` 에 결과가 들어 있습니다.
- `FAILED` 이면 `errorCode` 를 확인하세요 (`GEMINI_...`, `INPUT_ERROR`, `PARSE_ERROR` 등). "다시 시도" 버튼을 보여주면 됩니다.
- 폴링은 **최대 60초(약 20~30회)** 정도만 하고, 넘으면 "시간이 오래 걸리고 있어요" 로 안내하세요. 화면을 나가면 폴링도 꼭 멈추세요.

```ts
async function waitForAi(id: number, signal?: { cancelled: boolean }) {
  for (let i = 0; i < 30; i++) {
    await new Promise(r => setTimeout(r, 2000));
    if (signal?.cancelled) return null;
    const { data } = await api.get(`/ai-requests/${id}`);
    if (data.status === 'SUCCESS' || data.status === 'FAILED') return data;
  }
  return null; // 시간 초과
}
```

### 3-1. 영상 링크 / 글 / 사진에서 장소 뽑기

```jsonc
POST /ai-requests
{ "tripId": 1, "inputType": "LINK",  "sourceUrl": "https://youtube.com/..." }   // 유튜브 링크
{ "tripId": 1, "inputType": "TEXT",  "sourceText": "제주 가면 성산일출봉, ..." }  // 글 붙여넣기
{ "tripId": 1, "inputType": "IMAGE", "imageUrls": ["/files/...jpg"] }            // 4장의 업로드 결과 url
```

`places[]` 의 각 항목은 `name, address, category, description, lat, lng` 입니다.
**`lat/lng` 는 AI 추정값이라 부정확할 수 있습니다.** 지도에 핀을 꽂을 때는 `GET /places/search?keyword=<name>` (카카오맵) 결과를 골라 쓰는 것을 권장합니다.

### 3-2. 맞춤 추천 ⏳ (PR #7 머지 후 사용 가능)

```
GET  /travel-styles                         → 취향 목록 [{code, name}] (FOOD, CAFE, ...)
POST /recommendations                       → {tripId, companionType?, styleCodes?, count?(1~10, 기본 5)}
                                              응답은 AI 요청(위 폴링 패턴) → GET /ai-requests/{id} 로 SUCCESS 대기
GET  /recommendations?tripId=1              → 추천 카드 목록 (status: SUGGESTED / ACCEPTED / REJECTED)
POST /recommendations/{id}/accept           → 일정에 핀(addedBy="AI")으로 추가. body {dayId} 선택
POST /recommendations/{id}/reject           → 거절
```

- `companionType`: `SOLO` / `COUPLE` / `FAMILY` / `FRIEND`. 안 보내면 여행에 설정된 값, 취향도 여행 → 내 설정 순으로 자동 사용.
- **AI 요청이 SUCCESS 가 된 뒤** `GET /recommendations` 를 부르세요 (AI 요청 상태가 끝나기 전엔 목록이 비어 있습니다).
- `accept` 가 **422** 면 AI 가 준 가게를 지도에서 못 찾은 것입니다 (폐업·이름 변경 등). `message` 에 가장 가까운 후보 이름이 있을 수 있으니 그대로 보여주고, 사용자가 검색으로 직접 추가하게 하세요.

### 3-3. 동선 최적화 ⏳ (PR #8 머지 후 사용 가능)

AI(LLM)가 아니라 거리 계산이라 **폴링 없이 바로 결과**가 옵니다. "제안 → 확인 → 반영" 2단계입니다.

```
POST /route-optimizations                   → {tripId, redistribute?}  201, 일정은 아직 안 바뀜
GET  /route-optimizations?tripId=1          → 이력 (최신순)
GET  /route-optimizations/{id}              → 상세
POST /route-optimizations/{id}/apply        → 일정에 반영 (핀의 날짜·순서·이동수단 변경)
```

- 응답: `beforeDistanceM`(지금 일정의 총 이동거리) vs `totalDistanceM`(최적화 후), `days[].stops[]`(순서, 이동수단 `WALK`/`CAR`, 직전 장소와의 거리·시간).
  → "총 12.3km → 8.1km" 같은 개선 표시와 미리보기에 쓰세요. 시간·거리는 **추정치**(길찾기 아님)라고 작게 안내하는 걸 권장합니다.
- `redistribute` 기본 `true`: 날짜 미배정 핀 포함 전체를 일자들에 다시 나눠 담음. `false`: 날짜는 유지하고 날짜 안 순서만 변경.
- 일자(`itinerary-days`)가 하나도 없거나 핀이 없으면 **400**.
- **apply 가 409** → 제안을 만든 뒤 핀이 바뀌었거나 이미 반영한 제안입니다. 제안을 다시 만들게 하세요.
- 반영 후에는 `GET /itinerary-items?tripId=` 를 다시 불러 화면을 갱신하세요.

## 4. 사진·영상 업로드 → 주소 받기 → 저장

파일은 **먼저 업로드해서 주소(url)를 받고, 그 주소를 다른 API 에 문자열로 넣는** 2단계입니다.

```ts
const form = new FormData();
files.forEach(f => form.append('file', { uri: f.uri, name: f.name, type: f.type } as any)); // 필드 이름은 반드시 "file"
const { data } = await api.post('/files', form, {
  headers: { 'Content-Type': 'multipart/form-data' },
  timeout: 60000,
});
// data: [{ url, thumbnailUrl, mediaType: "IMAGE"|"VIDEO", size, width, height }, ...]  (올린 순서 그대로)
```

- 한 번에 1~10개. 응답 `url` 은 `/files/...` 형태의 **상대 경로**입니다. 이미지 `uri` 로 쓸 땐 `baseURL + url` 로 이어 붙이세요. (AI 사진 분석의 `imageUrls` 에는 이 상대 경로를 그대로 넣습니다. 업로드 API 로 올린 주소만 허용돼요.)
- `GET /files/**` 는 로그인 없이 열려 있어서 `<Image source={{uri}}>` 에 토큰을 안 붙여도 됩니다. (업로드 `POST` 만 인증 필요)
- 받은 `url` 을 쓰는 곳: 프로필 이미지(`PATCH /users/me/profile-image`), 기록/일기(`/diaries`), AI 사진 분석(`imageUrls`), 기록 사진·영상(`fileUrl`).

## 5. 자주 쓰는 흐름 한눈에

```
[여행 만들기]   POST /trips → POST /itinerary-days (1일차, 2일차, ...)
[핀 추가]       GET /places/search?keyword=성산일출봉 → 결과 하나 골라 POST /itinerary-items {tripId, dayId?, place:{...}}
                (place 의 name·latitude·longitude 필수, kakaoPlaceId 를 같이 보내면 같은 장소를 재사용)
[일정 보기]     GET /itinerary-items?tripId=  (일자·순서대로 정렬돼 옴, dayId 없는 건 "날짜 미배정")
[순서 바꾸기]   PATCH /itinerary-items/order {dayId, itemIds:[...]}  ← itemIds 는 그 날짜 핀 전체를 새 순서로
[AI 로 채우기]  3장
```

## 6. 연동하다 안 맞는 API 를 발견하면

백엔드 담당(정훈)에게 **요청 URL · 보낸 body · 받은 응답(status + body)** 을 같이 보내주세요 (Swagger 에서 같은 호출이 되는지도 확인해 주시면 가장 빠릅니다).
프론트가 쓰기 불편한 응답 모양이면 그것도 말씀해 주세요 — 지금 단계에서 바꾸는 게 제일 쌉니다.
