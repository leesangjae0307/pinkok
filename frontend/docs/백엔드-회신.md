# 백엔드 전달사항 회신 (프론트 → 백엔드)

작성일: 2026-10-18 · 브랜치: `feature/frontend`

전달해 주신 4가지 모두 확인했습니다. 프론트에서 끝낸 것과 서버에 부탁드릴 것을 나눠서 정리했습니다.

---

## 1. 서버에 추가를 부탁드리는 필드

### (1) `placesCount` — `GET /trips` 응답에 넣어 주세요

여행 목록과 여행 바텀시트 두 화면에서 "📍 장소 N개"를 바로 보여 줍니다.
없으면 목록에 뜬 여행마다 `GET /itinerary-items?tripId=` 를 한 번씩 더 불러야 해서(N+1) 목록 로딩이 그만큼 느려집니다.

### (2) 장소 평점 + 기록 수

핀 상세와 바텀시트에서 `rating`(평균 별점)과 `reviewsCount`(기록 개수)를 씁니다.
카카오 로컬 API 에는 평점·사진이 없으니, **우리 쪽 기록(다이어리)의 별점 평균과 기록 건수**로 내려 주시면 됩니다. 기록이 0건이면 `null` 로 주시고 프론트에서 "아직 기록 없음" 으로 처리하겠습니다.

### (3) 장소 썸네일

핀 목록·핀 상세·PinLog 클립 선택까지 5곳에서 장소 이미지를 씁니다.
**해당 장소의 첫 번째 기록 미디어 URL**을 `thumbnailUrl` 로 내려 주시면 충분합니다. 없으면 `null` — 프론트가 플레이스홀더를 깝니다.

### (4) `isLiked` 는 **빼 주세요**

프론트 전체에서 읽는 곳이 없는 죽은 필드였습니다. 타입에서 제거했습니다. 서버 작업 불필요합니다.

### (5) 같이 정해 두면 좋은 것 — `coverImageUrl` 이 빈 경우

`GET /trips` 의 여행 대표 이미지가 비는 경우가 많아 보입니다. 아래 중 어느 쪽으로 할지 정해 주시면 그에 맞춰 붙이겠습니다.

- (A) 서버가 **해당 여행 첫 핀의 썸네일로 대체**해서 항상 값을 채워 준다
- (B) 서버는 `null` 로 주고 **프론트가 지역별 기본 이미지**를 깐다

프론트는 (A)가 화면이 더 일관돼서 선호하지만, 서버 부담이 크면 (B)로 가도 됩니다.

---

## 2. 여행 스타일 — 서버 5개 코드로 교체 완료 (서버 작업 없음)

프론트에 있던 '힐링 / 맛집 / 액티비티 / 감성 사진' 4개 라벨을 버리고 서버 코드를 단일 기준으로 삼았습니다.
`frontend/src/constants/index.ts` 에 다음을 두고, 선택지를 만드는 모든 화면이 여기서만 가져옵니다.

| 서버 코드 | 화면 라벨 |
| --- | --- |
| `FOOD` | 맛집 |
| `SIGHT` | 관광 |
| `NATURE` | 자연 |
| `SHOPPING` | 쇼핑 |
| `CAFE` | 카페 |

- 상태값으로 저장하는 건 **코드**이고 라벨은 표시용입니다. API 로는 항상 코드만 나갑니다.
- 라벨 문구는 프론트가 바꿔도 서버에 영향 없습니다. 다만 **코드를 추가·변경하실 때는 알려 주세요** (목록에 없는 코드는 400 이라 선택지 자체를 서버 목록으로만 만들고 있습니다).
- 런타임에 `GET /travel-styles` 로 교체 가능한 구조로 짜 뒀습니다.

---

## 3. ID 타입 — 프론트를 `number` 로 전환 완료

말씀대로 프론트 타입을 숫자로 바꿨습니다. 타입체크 통과했습니다.

- `TripFolder` / `PlaceItem` / `TeamMember` / `PlaceRecord` / `VlogClip` / `NotificationItem` / `TripInvitation` 등 엔티티 ID 전부 `number`
- `PlaceRecord.pinId`, `PlaceRecord.userId`, `NotificationItem.targetId` 도 `number`
- 문자열로 **남겨 둔 것 2개** (서버 PK 가 아니어서 의도적입니다)
  - `ProfileAvatar.id` — 로컬 이미지 에셋 슬러그
  - `TeamInviteModal` 의 `loginId` — 화면에 `@` 로 보이는 로그인 아이디. 혼동 방지를 위해 필드명을 `userId` → `loginId` 로 바꿨습니다.

## 4. 소셜 로그인 — "준비 중" 안내로 변경 완료

네이버 / Google / 카카오 버튼은 **그대로 두고** 누르면 "간편 로그인은 준비 중입니다. 이메일로 로그인해 주세요." 안내가 뜹니다.

> 참고: 이 버튼 3개가 `onPress={onComplete}` 로 연결돼 있어서 **아무 자격증명 없이 앱 안으로 들어갈 수 있던 상태**였습니다. 같이 막았습니다.

## 5. 인증 연동은 붙였습니다 (0~1장)

가이드 0~1장대로 먼저 붙여 뒀습니다. 타입체크·린트·Metro 번들 모두 통과했고, 서버에 붙여서 실제로 토큰이 오가는지는 아직 확인 못 했습니다.

- `axios`, `@react-native-async-storage/async-storage` 설치
  - async-storage 는 **2.2.0** 으로 깔았습니다. 최신 3.x 는 TurboModule 전용인데 이 앱은 아직 `newArchEnabled=false` 라서요.
- `src/api/axios.ts` 교체 — `/api` 제거, 401 → refresh 단일화(single-flight), 실패 시 토큰 삭제 후 로그인 화면 복귀
- `src/services/tokenStore.ts`, `src/api/authApi.ts` 추가
- `App.tsx` — 앱 시작 시 저장된 토큰으로 로그인 유지, 토큰 만료 시 자동으로 로그인 화면
- 로그인 / 회원가입 / 로그아웃을 실제 API 로 연결
- baseURL 은 Android `http://10.0.2.2:8080`, 그 외 `http://localhost:8080` 입니다. **실기기 테스트용 LAN IP 나 터널 주소가 생기면 알려 주세요.**

## 6. 남은 질문 2개

(아바타 코드 매핑은 질문할 필요가 없었습니다. 서버 `static/images/avatars/{code}.png` 6개가 프론트 로컬 에셋과 **바이트 단위로 동일**해서 그대로 짝지었습니다: `F1`=책 읽는 겨울 / `F2`=은발 버킷햇 / `F3`=핑크 카메라 / `M1`=지도 보는 도시 / `M2`=윙크 헤드폰 / `M3`=선글라스.)

### (1) 이메일·아이디 중복 확인 엔드포인트가 있나요?

가입 화면에 "중복확인" 버튼이 있는데 전용 API 가 안 보여서, 지금은 **형식 검사만** 하고 실제 중복은 가입 시 409 메시지로 보여 줍니다.
`GET /auth/check-email?email=` 같은 게 있으면(또는 추가 가능하면) 입력 즉시 알려 줄 수 있습니다. 없어도 동작은 합니다.

### (2) 비밀번호 재설정 API 가 있나요?

`ResetPasswordScreen` 이 인증번호 발송·확인 화면인데 관련 API 가 문서에 없습니다. 지금은 목업 그대로(테스트 코드 778899) 두고 로그인 화면으로 돌려보냅니다. 계획이 있으면 알려 주세요.

## 8. 카카오·구글 등록용 키 값 (요청하신 것)

**팀원별로 값이 다르지 않습니다. 하나만 등록하면 됩니다.** 디버그 키스토어가 `frontend/android/app/debug.keystore` 로 **저장소에 커밋돼 있고** `build.gradle` 의 debug 서명이 그 파일을 직접 가리켜서, 저장소를 받아 빌드하는 팀원 전원이 같은 키로 서명합니다.

| 용도 | 값 |
| --- | --- |
| 카카오 키 해시 (Base64) | `Xo8WBi6jzSxKDVR4drqm84yr9iU=` |
| 구글 SHA-1 인증서 지문 | `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25` |

### ⚠️ 출시 전에 꼭 처리해야 하는 것

위 값은 **React Native 템플릿이 기본 제공하는 공개 디버그 키스토어**의 값입니다(검색하면 바로 나옵니다). 게다가 `android/app/build.gradle` 의 **release 빌드도 이 디버그 키로 서명**되게 되어 있습니다(템플릿 기본값, 주석에도 경고가 있음).

이 상태로 배포하면 누구나 같은 키로 서명한 앱을 만들 수 있어 카카오·구글 인증을 위조할 수 있습니다. 출시 전에 팀 전용 release 키스토어를 만들고 그 키의 해시·SHA-1 을 콘솔에 **추가 등록**해야 합니다. 그 키스토어 파일과 비밀번호는 저장소에 올리지 않습니다.

### 패키지명 — 지금 정하는 게 좋습니다

현재 `namespace`·`applicationId` 모두 `com.frontend` 인데, 이건 RN 이 폴더명(`frontend`)으로 만든 기본값이고 앱 식별자로 쓸 이름이 아닙니다. 스토어에 올리면 영구 고정이고, 나중에 바꾸면 콘솔 재등록은 물론 스토어상 완전히 다른 앱이 됩니다.

`com.pinkok.app` 같은 형태를 제안합니다. **소셜 로그인 콘솔 등록 전에 확정해 주시면** 프론트에서 Android `applicationId` · iOS 번들 ID · Java 패키지 경로까지 한 번에 바꾸겠습니다.
